# NullKey AI Support

NullKey AI — **The voice of your vault. The memory of your mind.**

## Get help

- **Bug:** use the repository's **Bug report** form.
- **Feature idea:** use the **Feature request** form.
- **General help / FAQ:** consult the project documentation first; if the problem remains reproducible, open a support issue with non-sensitive details.
- **Beta feedback:** report the issue and select **Beta** as the release channel.

## Privacy first

NullKey handles unusually sensitive information. **Never post clipboard contents, passwords, authentication tokens, typed text, vault contents, private documents, or personal information in a public GitHub issue.**

Diagnostic reports should be sanitized and should normally contain only technical metadata such as:

- NullKey version and build number
- Stable/Beta release channel
- Android version
- device model
- relevant sanitized error/diagnostic information

NullKey diagnostics must not collect clipboard contents, vault contents, passwords, authentication tokens, or typed text by default. Share user content only when you intentionally select and attach it.

## Security vulnerabilities

Do **not** open a public issue for an exploitable security vulnerability or a report that requires secrets/private data to demonstrate.

Use **GitHub Private Vulnerability Reporting / Security Advisories**:
https://github.com/johnshorttn/nullkey-ai-android/security/advisories/new

## Before reporting a bug

Confirm the problem on the newest build available in your current release channel when practical. Include clear reproduction steps, expected behavior, actual behavior, NullKey version/build, Android version, device model, and whether you are using Stable or Beta.

## Release channels

New feature releases are intended to progress through:

**Development → Internal Testing → Beta → Production**

Beta users receive new features before Stable/Production so real-world feedback can be addressed before broad rollout.
